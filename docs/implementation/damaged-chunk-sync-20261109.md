# 异常录音片段与同步隔离（0.4.8）

## 触发与确认范围

用户再次反馈手表提示“录音有未完成或损坏片段”并停止传输。这条横幅来自启动恢复检查，不能单凭横幅判断全部录音损坏或当前传输停在哪里。本轮检查时两台实体设备的开发连接不可用，尚未取得新的原文件和业务同步诊断。

代码确认两处会放大单个异常片段影响的路径：

- 重试 watchdog 反复只选最旧的超时系统副本；当其原文件无法通过校验时退出整轮检查，后面的健康副本无法获得重试。
- CaptureReady 中一个应为目录的条目实际为普通文件或符号链接，会让整轮恢复抛出 invalidDirectory。新增真实文件回归在修改前复现了这一失败。

## 修改与数据边界

传输层一次提供最多四个有序的超时候选。录音运行时分别校验原文件；无法重试的候选保留其系统副本，继续检查后续候选。取消系统副本前仍重新确认租约和实际进度，后台短授权最多取消一个副本；新文件只在 SDK 真正释放槽位后进入。每个候选继续受原有文件大小上限约束，没有伪造接收回执，也不以取消传输确认音频已送达。

恢复检查把异常目录条目记录为该片段的损坏问题，保留其内容或链接，不跟随链接读取，继续恢复其余音频。保留数据库、哈希、回执、删除权限和既有保留策略。瞬时 I/O、数据库及其他未识别错误继续明确报错。

0.4.8 同时包含已经合入的[手机录音播放器交互修复](player-interactions-20261109.md)。没有修改配对、sticker 文件或生成请求。

## 验证

- 480 项共享传输、录音和手机档案测试串行通过，覆盖原音保留、回执、重启恢复、旧版本迁移、损坏尾段、丢失回执及公平分页。
- 新增最旧副本无法重试时仍提供后续候选、候选数量和资格上限、快照后发生真实进度时拒绝旧取消决定的回归。
- 新增普通文件与符号链接两类异常目录隔离检查，确认健康音频仍待同步且哈希不变，异常条目也未被删除。
- 补全旧版本测试夹具还原时需移除的 analysis_windows_epoch_config_core 索引，使迁移测试在真实旧结构上运行；未改动生产迁移。
- 本轮不操作用户录音或清理设备队列。Release 构建、签名、实际安装版本和续传进展分别核对；共享测试通过不能替代真机同步验收。

本地诊断与测试日志保留在任务证据目录，不提交设备标识、原始日志或私人音频。
