# 手表与手机同步恢复（0.4.6）

## 触发与原因

真机出现手表显示“系统正在传送”，手机已有部分文件却长时间没有新的入库。观察到发送队列中的文件已在手机提交，回执有间歇性进展；不能据此认定所有录音已同步。开发连接的 RemotePairing 超时与应用内 WatchConnectivity 错误分别处理。

代码确认两个阻塞条件：

- 手机把对账响应的 background admission 作为是否发送普通回执的条件。交互式响应已经提交时 background 返回 deferred，或响应处于退避、刷新失败时，回执也会被跳过。
- 对账响应没有按系统选中的手表筛选；历史来源可能占用当前手表的发送与重试预算。

## 修改

每轮最多提交一条当前手表的对账响应，随后独立推进普通回执。响应刷新或传输失败保留其持久待办，不阻塞回执。已提交的响应会触发下一轮，避免逐条等自动重试计时。切换手表后停止另一来源的失败重试，保留其持久响应，不伪造已应用证明。

接收诊断增加按来源分组的待回执与待对账响应数量，区分历史设备与当前设备的积压。保持原来的接收提交、哈希校验、ReceiptApplied、重启恢复和原音清理边界。没有改动配对、录音数据、sticker 资源或生成请求。

## 验证

- 116 项协议、录音对账、分页与诊断测试通过，包括 503 个片段跨重启恢复丢失回执及传输的旅程。
- 首轮手机接收和控制失败测试 37 项通过；最终轮增加历史响应失败隔离，并覆盖后台授权、自动投递与 sticker 更新状态。
- 真机覆盖升级、实际版本、队列进展及后台系统调度需单独记录；测试和构建成功不等于真机全部同步完成。

测试产物在本轮独立目录，完成交付后按项目规则清理。未把私人录音、设备标识、配对信息或原始诊断提交到仓库。
