# 后台转录投递 · 2026-11-08

## 问题与行为

后台转录完成本来会调用 `sourcesChanged()`，但其 `active` 前台条件直接忽略了通知；离开前台后的回复续传结束也会关闭同一传输连接。结果是手机已经产生的内容只能等下一次前台轮询才上传，Mac 无法及时总结、整理和生成生活插画。

新内容通知现在持久标记待传修订，并启动一次有限上传。前台页面的轮询仍随页面生命周期停止；上传任务、前台使用和回复续传分别持有连接需求，全部结束后才挂起连接。后台上传只传来源，不读取记忆列表或启动聊天。

上传过程中发生的新归档变化不能被较早的回执清除；同批通知合并，成功回执保持原有去重语义。Mac 离线、系统拒绝执行时间、过期或进程重启时保留待传状态和原文。申请需要网络的 BGProcessing 重试，已有重试不会被持续录音不断推迟。启动、录音接收、转录进度、前台恢复和系统调度均可继续已有待传内容。

后台任务在 25 秒预算内结束，系统过期时同步归还执行时间并取消网络工作。BGProcessing 已获执行时间时不再依赖额外 UIKit 授权；旧过期回调不能取消新一轮任务。配对撤销仍阻止上传，不改变目的地、来源内容、插画身份或历史图片。

## 平台范围

系统决定后台任务的唤醒时机，不能保证锁屏后立即上传。请求只传已有的已授权录音转录，未增加常驻轮询、定位权限或其他后台能力。本轮不把日历、健康等来源的前台采集策略一并扩张。

遵循 Apple 的 [有限后台执行时间](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time) 和 [Background Tasks](https://developer.apple.com/documentation/backgroundtasks/) 机制；最低 iOS 18，默认字号，无 UI 样式改动。

## 验证与交付

测试覆盖后台变化触发、上传中变化合并、离线落盘后重启补传、不重放已确认来源、早回执不能清除新变化、执行时间拒绝与过期、旧回调隔离和系统授权完成。测试注入平台授权事件，不能替代真机系统调度验收。
