# Sticker 按录音时间显示位置

用户于 2026-11-10 明确要求：录音在哪里发生，就在那里显示，不等待离开地点。

原实现只接受已结束且至少五分钟的停留。今天的 sticker 已保存，但对应停留没有离开时间，因此坐标为空，手机跳过地图。已保存图片又被整体冻结，后到的位置也无法补入。

0.5.2 改为按录音时间匹配可靠 CoreLocation 位置：

- 正在发生的停留也可用于地图，以手机快照的观察时间和下一次到达为边界。相同到达时间已有结束记录时，不再使用遗留的未结束副本。
- 没有匹配停留时，可使用录音时段内采到的定位点；不借用几个小时前的孤立 GPS 点。
- 未结束停留或单次定位不编造到达/离开区间，地图卡片继续显示录音时间。
- 已保存但缺少坐标的 sticker 可以补位置，并发布原 ID 的元数据更新。原图、缩略图、摘要、生成请求与生成次数保持不变。

没有新增界面、标签或位置模式。手机现有地图和缓存即可接收这次元数据更新。

验证：46 项 life-illustration Python 测试全部通过，覆盖持续停留、后续到达、观察时间边界、录音时段内定位、保存后补位置、原图保留、权限变化及重复同步。用当前真实数据库副本回放时，当天 10 张已保存 sticker 从 0 张有坐标补为 10 张；所有图片哈希及生成状态保持不变，没有调用图片生成。

曾尝试“有轨迹时展示无定位卡片”的界面方案，用户明确简化要求后已撤回，相关模拟器测试结果不作为本次改动验收。最终代码仅调整 Mac 端位置匹配、元数据补全、生成约束文案与共享版本配置。
